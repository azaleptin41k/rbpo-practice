## 2. Список реальных уязвимостей (True Positives)

### 2.1. SQL Injection (Потенциальная SQL-инъекция)
*   **Файл:** `src/main/java/ru/mtuci/coursemanagement/service/CourseService.java`
*   **Строка:** 42
*   **Уровень опасности:** Medium (Средний), но потенциально High (Высокий)
*   **Правило Semgrep:** `java.spring.security.audit.spring-sqli.spring-sqli`
*   **Описание:** Обнаружено использование строковой конкатенации или небезопасной вставки аргументов в "сырой" (raw) SQL-запрос. Это позволяет злоумышленнику внедрить произвольный SQL-код.
*   **Предложение по устранению:**
    Необходимо отказаться от формирования SQL-запросов через сложение строк. Вместо этого следует использовать `PreparedStatement` или, в случае использования Spring Data JPA, именованные параметры.

    **Пример исправления:**
    ```java
    // БЫЛО (Уязвимый код):
    // String query = "SELECT * FROM courses WHERE name = '" + name + "'";
    
    // СТАЛО (Безопасный код):
    // Используем параметры (HQL/JPQL или Native Query с параметрами)
    @Query("SELECT c FROM Course c WHERE c.name = :name")
    List<Course> findByName(@Param("name") String name);
    ```

## 3. Список ложных срабатываний (False Positives)

### 3.1. Отсутствие CSRF-токена (Django Rule)
*   **Файлы:**
    *   `src/main/resources/templates/courses.html` (строки 17-22)
    *   `src/main/resources/templates/login.html` (строки 6-10)
    *   `src/main/resources/templates/login.html` (строки 14-19)
    *   `src/main/resources/templates/students.html` (строки 17-22)
*   **Правило Semgrep:** `python.django.security.django-no-csrf-token.django-no-csrf-token`
*   **Описание проблемы:** Semgrep сообщает, что в HTML-формах отсутствует токен защиты от межсайтовой подделки запросов (CSRF), ссылаясь на правила фреймворка **Django** (Python).
*   **Почему это ложное срабатывание:**
    1.  Проект написан на **Java (Spring Boot)**, а не на Python/Django. Сканер ошибочно применил правило для Python к HTML-шаблонам Java-проекта.
    2.  В Spring Security защита CSRF включена по умолчанию. При использовании шаблонизатора Thymeleaf (который, вероятно, используется, судя по расширению .html и структуре папок), токен CSRF добавляется автоматически в теги `<form>`, если используется атрибут `th:action`.
    3.  Даже если токен нужно добавить вручную, правило от Django здесь неприменимо технически.

### 3.2. Уточнение по CSRF (пересмотр)
При повторном разборе вывод о ложном срабатывании пересмотрен. Правило действительно написано для Django и сработало не по назначению. Но в `pom.xml` нет `spring-boot-starter-security`, поэтому встроенной CSRF-защиты Spring Security в приложении нет, и формы действительно уязвимы. Итог: **правило неподходящее, но проблема реальная** (CWE-352). Исправление — подключить Spring Security (CSRF включён по умолчанию) и использовать `th:action` в формах.
